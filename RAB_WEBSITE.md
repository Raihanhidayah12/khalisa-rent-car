## Rincian Lingkup Pekerjaan

### 1. Analisis kebutuhan dan alur bisnis
- **Aktivitas:** Inventarisasi halaman dan peran pengguna; pemetaan proses booking serta keputusan admin; penetapan daftar kebutuhan dan batas pekerjaan.
- **Hasil:** Daftar halaman, kebutuhan pelanggan/admin, urutan status booking, dan batas fitur yang masuk ke estimasi.

### 2. Desain UI/UX dan penyesuaian responsif
- **Aktivitas:** Struktur halaman dan hierarki informasi; penataan komponen publik dan admin; penyesuaian breakpoint desktop/ponsel; serta standarisasi ikon vektor modern Lucide tanpa emoji kartun.
- **Hasil:** Sistem antarmuka bersih, elegan, dan responsif pada seluruh perangkat mobile, tablet, maupun desktop.

### 3. Halaman publik, katalog, dan detail kendaraan
- **Aktivitas:** Beranda, navigasi, dan bagian informasi usaha; katalog, filter kategori, dan pengelompokan model; kartu/detail kendaraan beserta varian, stok, harga acuan, badge "Bisa Nego", dan konsultasi harga via WhatsApp; halaman syarat & ketentuan resmi 10 pasal serta cek status booking.
- **Hasil:** Pengunjung dapat mencari model melalui kategori; melihat foto, spesifikasi, harga, ketersediaan dan varian transmisi/mesin; opsi cepat "Nego via WA"; membaca syarat sewa & kebijakan privasi yang sah; serta membuka halaman cek booking mandiri.

### 4. Formulir booking dan alur WhatsApp
- **Aktivitas dan estimasi:**
  - Pilihan layanan (Dengan Supir, Lepas Kunci, Paket Acara), tanggal, jam, durasi bulan/hari/jam, dan batas minimum 12 jam.
  - Pemilihan model, varian, transmisi, kuantitas, opsi include tol, kalkulasi harga proporsional, dan opsi checkbox "Saya ingin ajukan nego harga via WhatsApp".
  - Validasi nama dan format nomor telepon internasional E.164, autocomplete alamat via Geoapify, dan opsi pengambilan lokasi perangkat via GPS.
  - Penyimpanan data booking ke Supabase, sinkronisasi mode sewa dengan batasan database, pembuatan kode booking unik (`KHS-XXXXXX`), dan penyusunan pesan WhatsApp serta tautan Google Maps penjemputan otomatis.

### 5. Dashboard admin dan pengelolaan operasional
- **Aktivitas:** Akses dashboard dan sesi admin persisten tanpa reset saat reload; pemrosesan booking, penugasan supir tervalidasi, ubah deal harga nego, dan modal detail booking; CRUD armada/foto dan manajemen tim supir; ringkasan keuangan Jakarta time, notifikasi Web Push & bel audio chime real-time, ekspor Excel dengan filter periode, dan manajemen akun admin.
- **Hasil:** Dashboard `/admin` terintegrasi, notifikasi suara dan push desktop otomatis saat pesanan masuk/selesai, fitur ubah harga deal nego terkunci, validasi kewajiban pilih supir sebelum konfirmasi status, ekspor data booking ke file `.xlsx` berformat rapi, statistik pemakaian jam-unit kendaraan, dan riwayat pesanan supir. Booking diselesaikan manual setelah kendaraan kembali dan diterima.

### 6. Integrasi Supabase dan kontrol akses
- **Aktivitas:** Konfigurasi koneksi frontend dan environment; integrasi autentikasi/role admin berbasis server claims; alur baca/tulis katalog, booking, supir, dan cloud storage; integrasi RPC ketersediaan, konfirmasi otomatis supir, fallback direct update penugasan supir, dan realtime postgres changes.
- **Hasil:** Frontend memakai Supabase URL dan anon key terisolasi; alur admin divalidasi ke server Supabase; ketersediaan supir dan armada diperiksa atomik; penugasan supir terlindung dari bentrok RPC; serta sinkronisasi realtime booking baru.

### 7. Pengujian, perbaikan bug, dan penguatan keamanan
- **Aktivitas:** Build dan pemeriksaan kode produksi; pengujian alur booking/admin dan perbaikan bug tipe database; penguatan keamanan web & anti-brute force form login.
- **Cakupan penguatan keamanan:** Penambalan dependensi berisiko; proteksi brute-force login admin otomatis (lockout 60 detik setelah 5 kali gagal); pengetatan izin database (RLS data pelanggan anonim); isolasi file foto di Cloud Storage; dan perbaikan format mata uang konsisten.

### 8. Deployment, optimasi SEO Google AI Overview, dan serah terima
- **Aktivitas:** Konfigurasi deployment Vercel dengan header keamanan HTTP lengkap; optimasi SEO teknis (`sitemap.xml`, `robots.txt`, dan Schema.org `AutoRental` JSON-LD lengkap dengan `primaryImageOfPage`); penyesuaian Title dan Meta Description high-CTR ramah Google Search & Gemini; integrasi meta thumbnail gambar mobil; penataan favicon multi-resolusi & `favicon.ico` di root; serah terima source code, panduan admin, dan dokumentasi.
- **Hasil:** Source code bersih, website berperingkat di Google Search & AI Overview, domain kustom `khalisarental.id` terkonfigurasi, panduan admin, dan garansi perbaikan bug 30 hari setelah serah terima.

## Alur Kerja Website

### Alur booking dari pelanggan sampai selesai

1. **Pelanggan memilih layanan dan jadwal:** Pelanggan memilih tanggal, jam mulai, dan durasi dalam bulan, hari, jam, atau kombinasinya. Kapasitas supir diperiksa secara otomatis. Opsi **Butuh supir** hanya dapat dipilih jika ada supir yang siap pada jadwal tersebut.
2. **Pelanggan memilih kendaraan:** Katalog menampilkan kendaraan yang ready dengan opsi **Bisa Nego**. Pelanggan memilih varian transmisi/mesin dan jumlah unit; harga acuan dan subtotal dihitung otomatis.
3. **Pelanggan mengisi data dan mengirim permintaan:** Nama, nomor WhatsApp, lokasi penjemputan, dan opsi pengajuan negosiasi harga divalidasi. Permintaan tersimpan berstatus **Menunggu** dengan kode booking unik (`KHS-XXXXXX`). Tautan pesan WhatsApp dan Google Maps disiapkan.
4. **Admin menerima notifikasi:** Browser admin membunyikan bel audio chime dan menampilkan Web Push Notification bahwa pesanan baru telah masuk.
5. **Admin memeriksa dan negosiasi harga (jika ada):** Admin meninjau rincian di dashboard `/admin`. Jika pelanggan mengajukan nego dan tercapai kesepakatan lewat WhatsApp, admin menekan tombol **Ubah Deal** di modal booking untuk memperbarui nominal harga deal.
6. **Admin menugaskan supir:** Untuk pesanan dengan mode sewa supir, admin wajib memilih supir yang tersedia terlebih dahulu pada kolom supir.
7. **Admin mengonfirmasi booking:** Admin mengubah status menjadi **Dikonfirmasi**. Database mengunci stok unit dan nominal harga deal terkunci (tidak dapat diubah kembali).
8. **Admin menyelesaikan booking:** Setelah waktu sewa selesai (admin menerima pemberitahuan desktop/suara), kendaraan diterima kembali, dan admin menandai booking menjadi **Selesai**.
9. **Ketersediaan diperbarui:** Supir kembali berstatus Tersedia dan armada memiliki jeda persiapan **5 jam** sebelum dapat disewa kembali.

```mermaid
flowchart TD
	A[Pelanggan pilih layanan dan jadwal] --> B{Ketersediaan supir sesuai?}
	B -- Tidak --> A
	B -- Ya --> C[Pilih kendaraan, varian, dan jumlah]
	C --> D[Isi kontak, jemput, dan opsi ajukan nego]
	D --> E[Permintaan tersimpan: Menunggu + kode booking]
	E --> F[Admin terima notifikasi chime & push di dashboard]
	F --> G{Pelanggan ajukan nego?}
	G -- Ya --> H[Admin & pemesan sepakat di WA, admin input Ubah Deal]
	G -- Tidak --> I{Perlu supir?}
	H --> I
	I -- Ya --> J[Admin tentukan supir di dropdown supir]
	I -- Lepas kunci --> K{Admin konfirmasi?}
	J --> K
	K -- Ditolak / dibatalkan --> L[Booking ditolak atau dibatalkan]
	K -- Konfirmasi --> M[Status Dikonfirmasi: Stok & harga deal dikunci]
	M --> N[Jadwal sewa selesai & kendaraan diterima]
	N --> O[Admin ubah status: Selesai]
	O --> P[Supir Tersedia kembali & armada jeda 5 jam]
	E -. Cek status dengan nomor WA + kode .-> Q[Halaman cek booking]
	M -. Status terbaru .-> Q
	O -. Status Selesai .-> Q
```
